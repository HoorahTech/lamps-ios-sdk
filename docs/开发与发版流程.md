# 开发与发版流程

日常在 GitLab 开发，只有发新版本时才同步 GitHub，并推到 CocoaPods 中心仓。

**不要来回改 `LampsSDK.podspec` 的 `s.source`。** 它必须长期指向 GitHub HTTPS，Trunk 和安装都依赖这个地址。

## 仓库与中心仓

| 角色 | 地址 | 何时用 |
| --- | --- | --- |
| 开发真源 | GitLab `origin`：`git@gitlab.hupu.com:HPBase/lamps-ios-sdk.git` | 日常 `git push` |
| 公开源码仓 | GitHub `github`：`https://github.com/HoorahTech/lamps-ios-sdk.git` | 发版时同步代码 + tag |
| 公有中心仓 | CocoaPods Trunk → [CocoaPods/Specs](https://github.com/CocoaPods/Specs.git) | `pod trunk push`，不能 git 直推 |
| 内部中心仓 | HPSpecs：`http://gitlab.hupu.com/iOSClient/HPSpecs.git` | 可选，`pod repo push` |

本机 remote：

```text
origin   → GitLab
github   → https://github.com/HoorahTech/lamps-ios-sdk.git
```

中心仓 **只收 podspec**。安装时 CocoaPods 按 spec 里的 `s.source` 去 clone **GitHub 的同名 tag**，不会去 GitLab。

## `s.source` 与私有中心仓

当前：

```ruby
s.source = { :git => 'https://github.com/HoorahTech/lamps-ios-sdk.git', :tag => s.version.to_s }
```

这 **不会阻止** `pod repo push` 到 HPSpecs。HPSpecs 只是把这份 spec 存进去。

会影响的是安装：

- 从 HPSpecs 或 Trunk 装 `LampsSDK`，代码都从 **GitHub tag** 拉
- GitHub 还没有这个 tag → lint / `pod install` 失败
- 只推了 GitLab、没同步 GitHub → 中心仓里的版本等于不可用

因此发版顺序必须是：**先把同一 commit 推到 GitHub 并打上 tag，再 push spec。**

不要为了推 HPSpecs 把 `s.source` 改回 GitLab。同一版本在 Trunk 和 HPSpecs 必须指向同一份公开源码。

## 日常开发

1. 只在 GitLab 上改代码、提 MR、`git push origin`。
2. **不要**每次提交都推 `github`。
3. **不要**用开发中的版本号去占 Trunk / HPSpecs。
4. 虎扑主工程联调走本地 path，不要依赖中心仓：

```ruby
pod 'LampsSDK', :path => '../../lamps-ios-sdk', :subspecs => [
  'Core', 'CSJAdapter', 'GDTAdapter', 'NoahAdapter', 'DevTools'
]
```

5. 本地可把 `use_binary` 临时改成 `false` 方便改源码；这个状态 **不要拿去发版**。切回后宿主重新 `pod install`。
6. 版本号先保持不动，直到确定要发。

| 动作 | GitLab `origin` | GitHub `github` |
| --- | --- | --- |
| 日常提交 | 要推 | 不推 |
| 发版同步 | 要推（真源） | 要推（给 `s.source` / Trunk） |
| 版本 tag | 建议打，作归档 | **必须打**，且与这次发版 commit 一致 |

## 发新版本

同一版本只能发一次。tag 和中心仓 spec **不能改、不能 force**。已发布的 `0.0.1` 在 GitLab / GitHub 上不是同一提交，**不要再动这个 tag**，有改动就升 `0.0.2`。

### 1. 改版本号并提交到 GitLab

同步改这些地方：

- `LampsSDK.podspec` 的 `s.version`
- `Lamps.sdkVersion`（`LampsSDK/Classes/Public/Lamps.swift`）
- 若本次也发独立 spec：`LampsDevTools.podspec`、`Lamps*Adapter.podspec`

发版要求：

- `use_binary = true`
- `LampsSDK/Binary/*.xcframework` 已进 git（需要则先 `./scripts/build_xcframeworks.sh`）
- `s.source` 仍是 GitHub HTTPS
- `s.default_subspecs = 'Core'`

```bash
git push origin main
```

### 2. 同步 GitHub

```bash
git push github main
```

### 3. 打 tag（同一 commit）

```bash
VERSION="$(ruby -e 'puts File.read("LampsSDK.podspec")[/s\.version\s*=\s*['\''"]([^'\''"]+)/, 1]')"
git tag -a "$VERSION" -m "LampsSDK $VERSION"
git push github "$VERSION"
git push origin "$VERSION"   # 归档用，可选但建议做
```

GitHub tag **必须有**，因为 `s.source` 用它。不要 `git push --force` tag。

发版前先查是否已占用：

```bash
git ls-remote --tags github "refs/tags/${VERSION}"
git ls-remote --tags origin "refs/tags/${VERSION}"
pod trunk info LampsSDK
```

Trunk 或 GitHub 已有该版本 → 停止，升版本再发。

### 4. 推公有中心仓（Trunk）

不能对 `CocoaPods/Specs` 做 `git push` / `pod repo push`。

```bash
export LANG=en_US.UTF-8
export CP_HOME_DIR="${HOME}/.cocoapods"

pod spec lint LampsSDK.podspec \
  --allow-warnings \
  --skip-import-validation \
  --use-static-frameworks \
  --sources='https://cdn.cocoapods.org,https://github.com/volcengine/volcengine-specs.git'

pod trunk me   # 未登录则先 register，点邮件后再继续

pod trunk push LampsSDK.podspec \
  --allow-warnings \
  --skip-import-validation \
  --skip-tests
```

成功后：https://cocoapods.org/pods/LampsSDK  
CDN 可能滞后，宿主安装失败先等再 `pod install --repo-update`。

### 5. 推内部中心仓（可选）

主工程若已钉公有源，可以不发 HPSpecs。要发时用**同一份** spec（`s.source` 仍是 GitHub），且 GitHub tag 已存在：

```bash
pod repo push hupu-iosclient-hpspecs LampsSDK.podspec \
  --allow-warnings \
  --skip-import-validation \
  --no-overwrite \
  --commit-message="Add LampsSDK ${VERSION}" \
  --sources='http://gitlab.hupu.com/iOSClient/HPSpecs.git,https://cdn.cocoapods.org,https://github.com/volcengine/volcengine-specs.git'
```

`pod repo push` 的第一个参数是本机仓名（`pod repo list` 核对），不要传 URL。

## 发版后宿主怎么引

虎扑主工程同时声明了公有 Specs 和 HPSpecs，必须钉源，避免抢到内部同名库：

```ruby
pod 'LampsSDK', '<version>', :source => 'https://github.com/CocoaPods/Specs.git', :subspecs => [
  'Core',
  'CSJAdapter',
  'GDTAdapter',
  'NoahAdapter',
  'DevTools'
]
```

默认 subspec 只有 `Core`。`pod 'LampsSDK'` 不会带广告。

- 宿主已有 `HPByteThirdParty` / `GDTMobSDK` / `NoahAdSdks` → 用 `*Adapter`
- 要让 Lamps 自己拉广告 SDK → 改用 `CSJ` / `GDT` / `Noah`，不要和对应 `*Adapter` 同时开

联调结束后去掉 `:path`，改回上面的版本号 + `:source`。

## 禁止

- 不要为发版来回改 `s.source`（GitHub ↔ GitLab）。
- 不要 force 移动已发布的 tag（尤其 GitLab 上的 `0.0.1`）。
- 不要覆盖 Trunk / HPSpecs 已有的同一版本。
- 不要在 `use_binary = false` 时 `pod trunk push`。
- 不要把 `.cursor/`、`Example/Pods` 推进 GitHub。
- 未提交的版本号不要打 tag。
